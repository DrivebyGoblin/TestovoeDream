# Mini Factory

Небольшая idle-фабрика для Android, выполненная как тестовое задание Unity Developer. На одном экране находятся три машины: первая доступна сразу, остальные можно открыть за игровую валюту. В проекте есть улучшения, временный Boost, офлайн-доход и покупка набора монет через Unity IAP.

## Запуск в Unity

1. Клонируйте репозиторий и откройте его корневую папку через Unity Hub.
2. Используйте Unity `6000.3.22f1`. Дождитесь восстановления пакетов и завершения компиляции.
3. Откройте сцену `Assets/_Project/Scenes/MachineCardUI.unity`.
4. Нажмите **Play**. Машины автоматически производят валюту. Через интерфейс можно открывать и улучшать машины, включать Boost и покупать монеты.
5. Чтобы посмотреть аналитику, откройте Console: события выводятся с меткой `[Analytics Event]`.

## Конфигурация и сохранения

Локальная конфигурация находится в `Assets/_Project/Configs/LocalGameConfig.asset`. В ней заданы параметры машин и Boost, лимит офлайн-дохода, переключатель IAP, ID продукта и награда. Текущие значения: Boost x2 на 30 секунд, лимит офлайн-дохода 24 часа и расходуемый продукт `coins_pack_small`, который выдаёт 1 000 монет.

Сохранение хранится в формате JSON в `PlayerPrefs` под ключом `GameSaveData`. В Unity Editor пункт **Tools > Clear Save Data** удаляет PlayerPrefs приложения и файл `save.json`, если он существует.

## Сборка для Android

1. В Unity Hub установите **Android Build Support**, включая SDK, NDK и OpenJDK.
2. В Unity откройте **File > Build Profiles**, выберите Android и переключитесь на этот профиль.
3. Убедитесь, что игровая сцена включена и стоит первой в списке сцен сборки; в репозитории она уже выбрана.
4. В Player Settings задайте **IL2CPP**, **ARM64**, минимальный API level **25** и автоматический Target API level. Идентификатор приложения: `com.DefaultCompany.urp_2d`.
5. Для локального APK отключите **Build App Bundle**. **Development Build** можно включить по желанию.
6. Собирайте проект за пределами `Assets`, например в `Builds/Android`. Для **Build And Run** подключите совместимое устройство с включённой USB-отладкой и подтвердите подключение компьютера на устройстве.

По сообщению автора, Android-сборка была вручную проверена на Realme C55, проблем не обнаружено. AI самостоятельно не собирал приложение и не проверял его на физическом устройстве.

Покупку можно проверить в Unity Editor через **Fake Store**. Реальный продукт в Google Play не создан, поэтому работа опубликованной покупки не заявляется. Кнопка покупки активируется после получения продукта; ошибки отображаются в интерфейсе.

## Системы и архитектура

- **Сборка зависимостей:** `Bootstrap` создаёт и связывает модели, UI, сохранения, аналитику и IAP. Основные зависимости создаются в `Awake`; асинхронная инициализация магазина запускается в `Start` с обработкой исключений.
- **Игровой цикл:** `GameLoop` останавливает онлайн-производство, пока приложение в фоне, и пропускает первый кадр после возврата, чтобы не учесть офлайн-интервал дважды. Он передаёт `Time.deltaTime` в `BoostService`, затем в `FactoryModel`. Общего tick manager нет; каждый кадр обновляются только эти две системы.
- **Фабрика и экономика:** `MachineModel` хранит состояние и уровень машины, `WalletModel` — баланс, а `FactoryModel` рассчитывает общее производство. Presenter-классы связывают модели с представлениями и действиями игрока.
- **Boost:** `BoostService` отслеживает оставшееся время и множитель. После окончания Boost производство возвращается к обычному значению.
- **Офлайн-прогресс:** `OfflineProgressService` рассчитывает прошедшее время, ограничивает оплачиваемый период и отдельно учитывает часть дохода, полученную при активном Boost. При восстановлении оставшееся время Boost уменьшается на всё реальное время отсутствия, даже если доход ограничен лимитом.
- **Жизненный цикл и сохранения:** `AppLifecycleScope` и `SaveService` сохраняют состояние машин, баланс, Boost и историю покупок. Сохранение выполняется при паузе, потере фокуса, выходе, выдаче покупки и применении офлайн-дохода. `ApplicationSession` объединяет `OnApplicationPause` и `OnApplicationFocus` в один интервал отсутствия. При возвращении доход применяется один раз к текущим моделям без повторной загрузки баланса и уровней. Если приложение закрывают в фоне, исходное время паузы сохраняется.
- **Конфигурация:** `GameConfig` содержит данные конфигурации, а `LocalGameConfig` — `ScriptableObject`, реализующий `IConfigProvider`. Модели получают готовые значения. Источник можно заменить в `Bootstrap`; Firebase Remote Config не подключён.
- **Внутриигровые покупки:** `UnityIAPService` скрывает Unity IAP за интерфейсом `IIAPService`; `StorePresenter` связывает интерфейс магазина, кошелёк и сохранения. Награда сохраняется до подтверждения покупки. ID в `PurchaseHistory` предотвращают повторную выдачу.
- **Аналитика:** `AnalyticsEvents` задаёт имена событий и параметры. `AnalyticsFacade` отправляет их зарегистрированным реализациям `IAnalyticsProvider`; подключён `ConsoleAnalyticsProvider`. Дополнительные провайдеры можно зарегистрировать в `Bootstrap`; ошибка одного провайдера не останавливает остальные.

### Формулы производства и улучшений

Для открытой машины, начиная с 1-го уровня:

- Производство в секунду = базовое производство × множитель производства^(уровень − 1)
- Цена следующего улучшения = базовая цена улучшения × множитель стоимости^(текущий уровень − 1)
- Общее производство = сумма производства открытых машин × множитель Boost (или 1 без Boost)

Например, при базовом производстве 10 и множителе 2 машина производит 10, затем 20, затем 40 монет в секунду. Закрытые машины ничего не производят. Цена открытия задаётся `BaseUnlockCost`. В конфигурации этим значениям соответствуют `BaseProduction`, `ProductionMultiplier`, `BaseUpgradeCost` и `CostMultiplier`.

### События аналитики

Проект отправляет события `game_started`, `machine_unlocked`, `machine_upgraded`, `boost_started`, `boost_finished`, `offline_income_applied`, `purchase_succeeded` и `purchase_failed`. События открытия и улучшения машины отправляются только после успешной оплаты. Восстановление сохранённого состояния не создаёт повторные события открытия или улучшения.

## Пакеты

- Unity IAP `5.4.3` — расходуемые покупки
- Unity Test Framework `1.6.0` — NUnit-тесты Edit Mode
- Unity UI `2.0.0` — UI, включая TextMeshPro
- Universal Render Pipeline `17.3.0` — рендеринг
- Input System `1.20` — ввод

В проекте остались пакеты шаблона 2D. Версии указаны в `Packages/manifest.json` и `Packages/packages-lock.json`. Firebase и AppMetrica не подключены.

## Тесты

Тесты находятся в `Assets/_Project/Tests/Editor/MiniFactoryLogicTests.cs` и `ApplicationSessionTests.cs`. В Unity откройте **Window > General > Test Runner**, выберите **EditMode** и нажмите **Run All**.

Девять тестов проверяют: окончание Boost в середине офлайн-периода; лимит офлайн-дохода; перевод часов назад; отсутствие изменений и уведомлений при нехватке средств; восстановление обработанной истории IAP без повторной награды; сохранение одного времени паузы при повторных callback-вызовах; обратный порядок callback паузы и фокуса; паузу без потери фокуса и повторную паузу; отсутствие повторного начисления при возврате.

После изменений жизненного цикла код скомпилировался, а все девять методов тестов были запущены отдельно с проверками NUnit: **9/9 пройдены**. Этот результат не заменяет запуск в Unity Test Runner или проверку Android-сборки. Файлы тестов находятся в папке `Editor` и не включаются в Android player build.
