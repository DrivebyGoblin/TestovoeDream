# Mini Factory

Небольшая idle-фабрика для Android, выполненная как тестовое задание Unity Developer.
На одном экране находятся три машины: первая открыта сразу, остальные покупаются за игровую валюту. Доступны улучшения, временный Boost, offline-доход и покупка набора монет через Unity IAP.

## Запуск в Unity

1. Клонировать репозиторий и открыть его корневую папку через Unity Hub.
2. Использовать **Unity 6000.3.22f1**. Дождаться восстановления пакетов и компиляции.
3. Открыть сцену `Assets/_Project/Scenes/MachineCardUI.unity`.
4. Нажать Play. Машины автоматически начисляют валюту; интерфейс позволяет открывать и улучшать машины, включать Boost и покупать монеты.
5. Для проверки аналитики открыть Console: события выводятся с меткой `[Analytics Event]`.

Локальные параметры находятся в `Assets/_Project/Configs/LocalGameConfig.asset`:

- параметры машин, Boost, лимит offline-дохода, включение IAP, ID продукта и награда.
- Текущие значения: Boost ×2 на 30 секунд, offline-лимит 24 часа, consumable `coins_pack_small` на 1000 монет.

Сохранение: JSON в PlayerPrefs, ключ `GameSaveData`.
Для сброса в редакторе есть **Tools → Clear Save Data**.
Эта команда удаляет все PlayerPrefs приложения, а также `save.json`, если такой файл существует.

## Android build

1. Через Unity Hub установить для этой версии Editor модуль **Android Build Support**, включая SDK, NDK и OpenJDK.
2. Открыть **File → Build Profiles**, выбрать Android и переключить активную платформу.
3. В списке сцен оставить включённой `Assets/_Project/Scenes/MachineCardUI.unity` и поставить её первой. В репозитории эта сцена уже выбрана для сборки.
4. Проверить Player Settings. В репозитории настроены IL2CPP, ARM64 и Minimum API Level 25; Target API выбирается автоматически. Текущий Application Identifier: `com.DefaultCompany.urp_2d`.
5. Для локальной проверки собирать APK, отключив Build App Bundle. При необходимости включить Development Build.
6. Нажать Build и сохранить результат вне Assets, например в `Builds/Android`. Для Build And Run подключить совместимое Android-устройство с включённой USB-отладкой и разрешить подключение компьютера.

IAP предусмотрен для проверки через Fake Store в Unity Editor. Реальный продукт Google Play не создан; работоспособность покупки в опубликованном Android-приложении не заявляется. Кнопка покупки доступна после получения продукта, ошибки подключения отображаются в интерфейсе.

## Системы и архитектура

- **Bootstrap** — вручную создаёт и связывает модели, UI, сохранения, аналитику и IAP. Основная сборка выполняется в Awake, асинхронное подключение магазина — в Start с обработкой исключений.
- **GameLoop** — останавливает онлайн-производство в фоне, пропускает первый кадр после возврата, чтобы не учитывать offline-интервал повторно, и передаёт `Time.deltaTime` сначала BoostService, затем FactoryModel. Универсальный менеджер тиков не вводился: обновляются только две системы.
- **Machines / Economy / Factory** — MachineModel хранит состояние и уровень машины, WalletModel управляет балансом, FactoryModel начисляет общий доход. Presenter связывает модель с View и обрабатывает действия игрока.
- **BoostService** — хранит оставшееся время и множитель. При истечении Boost производство возвращается к обычному.
- **OfflineProgressService** — рассчитывает доход между двумя временными отметками, ограничивает оплачиваемую длительность и отдельно учитывает усиленный участок. При восстановлении оставшийся Boost уменьшается на всё реально прошедшее время, независимо от лимита дохода.
- **AppLifecycleScope / SaveService** — загрузка машин, баланса, Boost и истории покупок; сохранение при сворачивании, потере фокуса, выходе, выдаче покупки и применении offline-прогресса. ApplicationSession объединяет OnApplicationPause и OnApplicationFocus в один интервал отсутствия. При возврате доход применяется один раз к текущим моделям, без повторной загрузки баланса и уровней. При закрытии в фоне сохраняется исходная отметка сворачивания.
- **Configuration** — GameConfig содержит данные, LocalGameConfig хранит их в ScriptableObject и реализует IConfigProvider. Игровые модели получают готовые значения. Для другого источника нужно изменить сборку зависимостей в Bootstrap; Firebase Remote Config не подключён.
- **IAP** — UnityIAPService изолирует API Unity IAP за IIAPService. StorePresenter связывает магазин, интерфейс, кошелёк и сохранения. Награда сохраняется до подтверждения покупки; PurchaseHistory хранит ID обработанных транзакций и предотвращает повторную выдачу для уже обработанного ID.
- **Analytics** — AnalyticsEvents задаёт события и параметры, AnalyticsFacade рассылает их всем зарегистрированным IAnalyticsProvider. Подключён ConsoleAnalyticsProvider. Дополнительный провайдер регистрируется в Bootstrap; ошибки одного провайдера не прерывают отправку остальным.

Формулы для открытой машины (начальный уровень — 1):

- Производство в секунду = базовое производство × множитель производства^(уровень машины − 1).
- Цена следующего улучшения = базовая цена улучшения × множитель цены^(текущий уровень машины − 1).
- Общая производительность = сумма производства открытых машин × текущий множитель Boost (1, если Boost неактивен).

Знак `^` обозначает возведение в степень. Например, при базовом производстве 10 и множителе 2 машина производит 10 монет/с на уровне 1, 20 на уровне 2 и 40 на уровне 3. Закрытая машина ничего не производит. Цена открытия берётся напрямую из BaseUnlockCost.

В конфигурации этим величинам соответствуют BaseProduction, ProductionMultiplier, BaseUpgradeCost и CostMultiplier.

В аналитике реализованы:

- `game_started`;
- `machine_unlocked`;
- `machine_upgraded`;
- `boost_started`;
- `boost_finished`;
- `offline_income_applied`;
- `purchase_succeeded`;
- `purchase_failed`.

События машин отправляются после успешной оплаты, а восстановление сохранения не считается новым открытием или улучшением.

## Тесты и проверка

Файлы: `Assets/_Project/Tests/Editor/MiniFactoryLogicTests.cs` и `ApplicationSessionTests.cs` в той же папке.

Запуск: **Window → General → Test Runner → EditMode → Run All**.

Девять unit-тестов проверяют:

1. Начисление offline-дохода, когда Boost заканчивается в середине отсутствия.
2. Ограничение дохода максимальным временем offline production.
3. Отсутствие начислений при переводе часов назад.
4. Отказ списания при нехватке валюты без изменения баланса и уведомлений.
5. Восстановление истории обработанных IAP-транзакций без дублей.
6. Сохранение исходного времени ухода в фон и однократный возврат при повторных callbacks.
7. Обратный порядок OnApplicationPause / OnApplicationFocus.
8. Паузу без событий фокуса и повторное сворачивание.
9. Отсутствие двойного начисления при повторном событии возврата.

Тесты используют фиксированные даты, не требуют магазина, сети или ожидания реального времени.
Папка Editor исключает их из Android player.
После исправления lifecycle выполнены компиляция актуального кода и отдельный запуск девяти тестовых методов с настоящими NUnit assertions: 9/9 успешно.
Этот запуск не заменяет проверку через Unity Test Runner и Android build.

**Устройство и результаты Android-проверки:** Realme C55. По результатам ручной проверки автора Android-сборка работала корректно, проблем не обнаружено.
